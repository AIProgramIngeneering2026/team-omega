# Как работать над Omega Rooms

## Задачи, ветки и коммиты

Для каждой задачи создаём issue с исполнителем и критериями готовности. Изменения вносим через отдельную ветку и pull request в `main`; прямые изменения `main` не используем.

Ветка называется `<тип>/<краткая-тема>`: например, `docs/room-scenarios`, `feature/booking-job` или `codex/p1-suntsov-scenarios` для работы с ИИ. При наличии номера issue его можно добавить в имя ветки. Название должно позволять понять задачу без открытия PR.

Коммит начинается с типа и краткого описания действия: `docs: describe booking conflicts`, `feat: add booking job`, `fix: reject overlapping bookings`. Используем `docs`, `feat`, `fix`, `test` или `chore` по смыслу; один коммит не должен смешивать независимые задачи.

## Pull request и review

В описании PR указываем, что изменено, ссылку на issue, как проверено изменение и какие ограничения остались. Автор проверяет diff перед отправкой. Review делает другой участник команды: сверяет результат с критериями issue, задаёт вопросы или оставляет замечания по существу. Автор исправляет замечания или объясняет решение; после этого reviewer повторно смотрит изменения. Сливаем PR после review.

## Definition of Done

Задача считается завершённой, когда:

1. Результат соответствует критериям приёмки issue.
2. Связанные документы и примеры обновлены; противоречий с уже описанными сценариями нет.
3. Для кода добавлены нужные проверки, локальные тесты и CI проходят, если они есть в проекте.
4. PR связан с issue, прошёл содержательное review другого участника и влит в `main`.
